# Headless v2.1.43 compatibility integration

## Provenance and scope

The supplied `chat-on-steroids-2.1.43.zip` identifies upstream commit
`457fc3039a415a6b5484a18cd50f4d2f788d0739`. A read-only fetch of upstream's
`refs/tags/v2.1.43` returned exactly that commit. All 1,485 archive files were
verified against their Git blob identities. The reference was extracted outside
the writable checkout. No upstream branch, PR, issue or release was modified.

Headless baseline: `324a7defee0265bbd3c8e2536e32b93c5a1928cd` (PR #33).
Shared ancestor: `f64ee51bf33a0ef194b7b0849d52c4aef9ac07d9`.
The upstream interval contains 901 commits, including 498 non-merge commits,
and changes 620 files. This integration merges the immutable upstream history,
retaining original authorship, license, contributors and Headless history.
See [the complete commit map](v2.1.43-commit-map.tsv) and
[the file disposition map](v2.1.43-file-map.tsv).

`PORTED` in those maps means source incorporated, including explicit adaptation;
it does not certify every provider, operating system or optional feature. Test,
bundle, installed and live acceptance are separate gates. A mixed commit retains
its runtime changes while excluded workflow/docs paths follow the file map.

## Compact & Resume investigation

The existing fork already retains strict native final UUID enrichment, late
recorder reconciliation, same-id reopening fences, three-pickup persistence,
observation-only writing pickups and exact source/destination dispatch custody.
These mechanisms are retained, including negative regression tests.

An upstream defect fix addresses a stopped source turn whose delayed `turn_end`
arrives after the authored handoff question. Headless previously counted that old
turn as another answer and refused an otherwise exact summary. This integration
excludes it only when independent durable chronology proves that generation
started before the request and it has no answering content inside the interval.
An unknown competing generation with a lost start remains ambiguous. A remount
without a generation can be joined only through the current completed boundary's
exact native final UUID. No transcript row is assigned a fabricated generation.

Source Send retains Headless's revocable run/document/route witness, including
its original assistant baseline, alongside upstream edit/resubmit handling.
Readiness diagnostics use Headless's durable `sourcePending` protocol; returning
page-helper evidence can retry the same predispatch obligation. No missing ACK
can authorize another native Send. Genuine missing/competing identity requires
exact late evidence or operator reconciliation and stays blocked after pickup
exhaustion, without a fourth reload.

## Production preflight and deployment blocker

Read-only SSH inspection found installed source revision
`324a7defee0265bbd3c8e2536e32b93c5a1928cd`. The managed target and backend,
browser, Discord, display and private session services were running. The
Control API answered health successfully; 20 sessions included one open provider
turn. No active workers were projected by the read-only agents endpoint.
All four discovered source checkouts were inspected; the main service checkout
has an uncommitted package change and was left untouched. No service was stopped,
profile reloaded, session modified or backup created.

The supported [reviewed rollout](../headless-long-run-rollout.md#approved-maintenance-and-verified-backup)
requires a stopped, flushed stack and verified encrypted backup before code
replacement. The user expressly forbids creating a new backup and instructs that
mandatory-backup conflicts be reported. Consequently deployment is blocked;
existing rollback artifacts are preserved and no protection is bypassed.

The installed revision above is the pre-upgrade revision. Source/bundle success
must never be reported as an installed upgrade or authenticated acceptance.


Private read-only metadata classification found three awaiting-summary captures with
reported identity errors. Two multiple-generation intervals contained a proven
pre-anchor generation. One missing-identity interval held an unowned final with a
native message UUID but no recorded generation or completed boundary; its UUID alone
cannot safely reconstruct ownership. The latter remains blocked unless independent
late evidence arrives. Neither the raw records nor their text/identities were changed.
Unchanged capture refusals are now logged only when the durable diagnostic changes;
a failed-first regression observed four repeated warnings before this fix and one after.
